基于 URMA 构建的 coro_rpc 接口使用说明

本文说明 yalantinglibs 中如何启用 URMA 作为 coro_rpc 的传输层， 包括构建方式、最小服务端和客户端、常用配置、附件数据传输、性能测试与排障建议。

使用流程 构建 服务端 客户端 配置项 附件传输 验证与压测 排障

一、整体使用流程

1. 编译启用 URMA 使用 CMake 打开 YLT_ENABLE_URMA，并确保系统已安装可用的 URMA 运行环境和设备驱动。
2. 服务端初始化 URMA 创建 coro_rpc_server 后调用 server.init_urma()，再注册 RPC handler 并启动服务。
3. 客户端初始化 URMA 创建 coro_rpc_client 后调用 client.init_urma()，再连接服务端地址并发起 RPC。
4. 按需设置参数 通过 coro_io::urma_socket_t::config_t 设置设备名、EID、队列深度、buffer 大小和内存上限。

URMA 模式仍然复用 coro_rpc 的 handler 注册、call、call_for、send_request 等上层接口；区别主要是服务端和客户端需要先初始化 URMA 传输。

二、构建方式

在仓库根目录执行以下命令，启用 URMA 并构建示例：

cmake -S . -B build -DYLT_ENABLE_URMA=ON -DBUILD_EXAMPLES=ON
cmake --build build --target coro_rpc_urma_example -j

如果需要构建压测工具：

cmake --build build --target coro_rpc_urma_benchmark -j

如果目标提示需要 -DYLT_ENABLE_URMA=ON，说明已有 build 目录没有打开该选项，需要重新执行 CMake configure。

三、服务端写法

最小服务端只需要定义 RPC 函数、初始化 URMA、注册 handler、启动服务。

#include "ylt/coro_rpc/coro_rpc_server.hpp"

using namespace coro_rpc;

std::string_view echo(std::string_view data) {
  return data;
}

int main() {
  coro_rpc_server server{/*thread_num*/ std::thread::hardware_concurrency(),
                         /*port*/ 9000};

  server.init_urma();
  server.register_handler<echo>();

  auto ec = server.start();
  if (ec) {
    std::cerr << "start server failed: " << ec.message() << std::endl;
    return 1;
  }

  return 0;
}

server.init_urma() 会让服务端在握手阶段把连接升级为 URMA 传输。若不调用该函数， coro_rpc 默认使用 TCP。

四、客户端写法

客户端需要在 connect 前调用 init_urma。连接地址仍使用 host:port 格式。

#include "async_simple/coro/SyncAwait.h"
#include "ylt/coro_rpc/coro_rpc_client.hpp"

using namespace async_simple::coro;
using namespace coro_rpc;
using namespace std::chrono_literals;

std::string_view echo(std::string_view data);

Lazy<void> request() {
  coro_rpc_client client;

  if (!client.init_urma()) {
    std::cerr << "init URMA client failed" << std::endl;
    co_return;
  }

  auto ec = co_await client.connect("127.0.0.1:9000");
  if (ec) {
    std::cerr << "connect failed: " << ec.message() << std::endl;
    co_return;
  }

  auto result = co_await client.call_for<echo>(30s, "hello urma");
  if (!result) {
    std::cerr << "rpc failed: " << result.error().msg << std::endl;
    co_return;
  }

  std::cout << result.value() << std::endl;
}

int main() {
  syncAwait(request());
}

对于需要流水线或连接复用的场景，可以继续使用 coro_io::client_pool<coro_rpc_client>。 每个连接内部仍由 coro_rpc_client 完成 URMA 初始化与请求发送。

五、常用 URMA 配置

服务端和客户端都可以传入同一个 coro_io::urma_socket_t::config_t：

#include "ylt/coro_io/urma/urma_socket.hpp"

coro_io::urma_socket_t::config_t urma_config{
    .cq_size = 128,
    .recv_buffer_cnt = 64,
    .send_buffer_cnt = 64,
    .buffer_size = 4 * 1024,
    .max_memory_usage = 256ull * 1024 * 1024,
    .device_name = "bonding_dev_0",
    .eid_index = 0,
    .tp_type = URMA_CTP,
};

server.init_urma(urma_config);
client.init_urma(urma_config);
字段 默认值 说明
cq_size 128 完成队列大小。
recv_buffer_cnt 8 接收队列 buffer 数量。并发或大包场景可适当增大。
send_buffer_cnt 4 发送队列 buffer 数量。吞吐压测时通常需要增大。
buffer_size 4096 URMA 分片发送大小。CTP 场景默认使用 4KB。
max_memory_usage 256 MiB URMA buffer pool 的进程级内存上限。
device_name 空字符串 为空时自动选择第一个 URMA 设备；生产环境建议显式设置。
eid_index 0 选择设备上的 EID 下标。
tp_type URMA_CTP 传输类型，当前示例默认使用 CTP。

配置必须在 connect 或 start 之前完成。服务端和客户端的设备名、EID、传输类型需要和实际网络环境匹配。

六、附件数据传输

对大块 payload，除了把数据作为普通 RPC 参数传入，也可以用 attachment 发送。 URMA benchmark 中的 attach_sink 模式就是用 attachment 测试快路径。

客户端设置请求 attachment

std::string payload(1024 * 1024, 'x');

client.set_req_attachment(payload);
auto result = co_await client.call_for<upload>(30s, payload.size());

客户端预设响应 attachment buffer

std::vector<char> recv_buffer(1024 * 1024);

client.set_resp_attachment_buf(recv_buffer);
auto result = co_await client.call_for<download>(30s);

std::string_view attachment = client.get_resp_attachment();

服务端读取请求 attachment 并设置响应 attachment

#include "ylt/coro_rpc/coro_rpc_server.hpp"

void upload(std::size_t expected_size) {
  auto* ctx = coro_rpc::get_context();
  auto attachment = ctx->get_request_attachment();

  if (attachment.size() != expected_size) {
    throw std::runtime_error("bad attachment size");
  }
}

void echo_attachment() {
  auto* ctx = coro_rpc::get_context();
  auto attachment = ctx->get_request_attachment();
  ctx->set_response_attachment(attachment);
}

如果启用了 GPU 相关能力，可以使用 set_req_attachment2、set_resp_attachment_buf2 和 get_resp_attachment2，通过 coro_io::data_view 携带 gpu_id。 gpu_id == -1 表示普通 CPU 内存。

七、验证与压测

仓库提供了 coro_rpc_urma_benchmark，可用于同机或跨节点验证。

服务端节点

./build/output/examples/coro_rpc/coro_rpc_urma_benchmark server \
  --host 0.0.0.0 \
  --port 9001 \
  --device bonding_dev_0

客户端节点

./build/output/examples/coro_rpc/coro_rpc_urma_benchmark client \
  --host <server-ip> \
  --port 9001 \
  --device bonding_dev_0 \
  --mode both \
  --payload 64 \
  --latency-iters 10000 \
  --connections 128 \
  --duration 30

测试大包 attachment 快路径：

./build/output/examples/coro_rpc/coro_rpc_urma_benchmark client \
  --host <server-ip> \
  --port 9001 \
  --mode throughput \
  --rpc attach_sink \
  --payload 1048576 \
  --connections 64 \
  --pipeline-depth 8 \
  --queue-depth 128 \
  --duration 30

八、常见问题排查

现象 检查点
编译时没有 URMA 示例目标 确认 CMake configure 已带 -DYLT_ENABLE_URMA=ON，并且安装了 URMA 头文件和库。
init_urma 返回失败 检查设备名、EID、驱动状态、URMA 运行时是否可用；先用默认配置或实际设备名重试。
客户端连接失败 确认 TCP 握手地址可达，服务端已调用 init_urma 并启动，防火墙未阻断端口。
高并发出现发送或接收错误 降低连接数或 pipeline depth，或增大 recv_buffer_cnt、send_buffer_cnt、max_memory_usage。
吞吐不符合预期 先用 benchmark 的 --transport raw 排除 RPC 层开销，再对比 echo、sink、attach_sink。

参考代码位于 src/coro_rpc/examples/urma_example/urma_example.cpp， 压测说明位于 src/coro_rpc/examples/urma_benchmark/README.md。
